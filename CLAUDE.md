# CarLyrics — Personal Spotify Lyrics Live Activity for CarPlay

## Context
- Personal-use iOS app (never published to the App Store).
- The developer is on **Windows with no Mac**. All builds happen on **GitHub Actions macOS runners**. The resulting unsigned `.ipa` is installed on the iPhone with **Sideloadly** using a free Apple ID (re-signs the app + extension).
- The user has **Spotify Premium**.
- Talk to the user in **English**. Code, comments and commit messages in English.

## Goal
Show the currently playing Spotify line of lyrics as a **Live Activity**. On iOS 26+, Live Activities appear on the CarPlay dashboard, which is the main target. No CarPlay app/entitlement is needed.
The Live Activity shows: the current lyric line (large), the next line (smaller, dimmed), and optionally song title/artist.
Lyrics must work in **Hebrew and English** (correct RTL/LTR per line).

## Architecture
- SwiftUI app, deployment target iOS 17.0 (CarPlay display needs iOS 26 on device; don't require it).
- Project generated by **XcodeGen** from `project.yml` (never hand-edit or commit `.xcodeproj`).
- Targets:
  1. `CarLyrics` (app)
  2. `CarLyricsWidget` (Widget extension with the `ActivityConfiguration`)
  - `Shared/LyricsActivityAttributes.swift` compiled into both targets.
- Info.plist (app): `NSSupportsLiveActivities = YES`, `NSSupportsLiveActivitiesFrequentUpdates = YES`, `UIBackgroundModes = [audio]`, URL scheme `carlyrics`.
- No App Groups, no push notifications, no special entitlements (must work with a free Apple ID).

### Spotify
- Web API, Authorization Code **with PKCE** (no client secret). `ASWebAuthenticationSession`.
- Redirect URI: `carlyrics://callback`. Scopes: `user-read-currently-playing user-read-playback-state`.
- Client ID lives in `CarLyrics/Config.swift` (it is not a secret with PKCE).
- Store refresh token in Keychain; refresh access token automatically.
- Poll `GET /v1/me/player/currently-playing` every ~3s. Between polls, estimate position locally from `progress_ms` + time since response. Handle 204 (nothing playing), 401 (refresh), 429 (respect Retry-After).

### Lyrics
- Primary source: **LRCLIB** (free, no key).
  1. `GET https://lrclib.net/api/get?track_name=&artist_name=&album_name=&duration=`
  2. Fallback: `GET https://lrclib.net/api/search?track_name=&artist_name=`, pick best match by duration (±3s) that has `syncedLyrics`.
  - Send a `User-Agent` header like `CarLyrics/1.0 (personal)`.
- Parse LRC (`[mm:ss.xx] text`, multiple timestamps per line, ignore metadata tags).
- If only `plainLyrics` exist, show "No synced lyrics" + title instead of guessing timing.
- Cache lyrics per Spotify track ID (in memory + small disk cache).
- Keep the lyrics provider behind a `LyricsProvider` protocol so more sources can be added later.

### Hebrew / RTL
- Per line: if it contains Hebrew characters (U+0590–U+05FF), render RTL with trailing alignment; otherwise LTR. Apply in both the app and the Live Activity views.
- Normalize search terms (strip "feat.", "- Remastered", parentheses) and retry LRCLIB search; Israeli tracks may have Hebrew or transliterated metadata.

### Live Activity
- `ContentState`: `currentLine`, `nextLine`, `isRTLCurrent`, `isRTLNext`, `trackTitle`, `artist`.
- Update the activity only when the line changes (not every poll).
- Support `.supplementalActivityFamilies([.small])` and branch on `@Environment(\.activityFamily)` — the `.small` layout is what CarPlay / watchOS show. Big readable text, dark background, max 2 lines for current line.
- Also provide lock screen + Dynamic Island layouts (simple).
- End the activity when playback stops for > 2 minutes or the user taps "Stop".

### Background execution
- iOS suspends apps in the background. Keep alive by playing a **silent audio loop** via `AVAudioSession` category `.playback` with option `.mixWithOthers` (must never interrupt Spotify). Start it only while a session is active.
- This is acceptable because the app is personal and never goes through App Review.

### App UI (simple)
- "Connect Spotify" button, status line, "Start" / "Stop" buttons, preview of current/next line, small debug log view (last ~50 events) to help diagnose issues from the car.

## Build & delivery (GitHub Actions)
- Workflow `.github/workflows/build.yml`, triggered on push to `main` and `workflow_dispatch`.
- `runs-on: macos-latest`; `brew install xcodegen`; `xcodegen generate`;
  `xcodebuild archive -scheme CarLyrics -configuration Release -destination 'generic/platform=iOS' -archivePath build/CarLyrics.xcarchive CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY=""`
- Package: copy `CarLyrics.app` into `Payload/`, zip to `CarLyrics.ipa`, upload as artifact `CarLyrics-ipa`.
- Verify the widget extension `.appex` is inside `CarLyrics.app/PlugIns/` before uploading (fail the build if missing).

## Dev loop (Claude Code)
1. Make changes, commit, `git push`.
2. `gh run watch` on the latest run. If it fails, read logs with `gh run view --log-failed`, fix, push again.
3. On success: `gh run download -n CarLyrics-ipa -D ./out` and tell the user the IPA is ready to install with Sideloadly.
- Keep builds few: batch fixes; each macOS build costs runner minutes.

## Phases
1. Skeleton: project.yml, app + widget, workflow builds a valid IPA. A test button starts a Live Activity with fixed text.
2. Spotify login + now playing shown in app.
3. LRCLIB + LRC parsing + synced line in app.
4. Live Activity updates + background audio keep-alive.
5. Polish: RTL, CarPlay `.small` layout, error states.
6. (Later, optional) translation line under the lyric.
